# repo-summarize v2 Book Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the bash `repo-summarize` with a single-file Python tool that turns a repository into a short, ordered, source-cited "book" (`INDEX.md`, chapters, `FILES.md`, `UNCERTAINTIES.md`, `provenance.json`). It runs its AI backend inside an OS sandbox and publishes recoverably.

**Architecture:** One stdlib-only Python file, `bin/repo-summarize`, organized into the spec's sections. Data flows: discover → snapshot → backend check → catalog → plan → attach → chapters → index → render into staging → validate → journalled publish. The model only returns JSON. The tool pastes all code, builds all links, and assigns all labels.

**Tech Stack:** Python ≥ 3.12 (stdlib only), `uv run --script` shebang, pytest via `uv run --with pytest`, `git`, macOS `sandbox-exec` / Linux `bwrap`, and `agy` as the default backend.

**Spec:** `docs/superpowers/specs/2026-10-20-book-mode-design.md` (rev 3). Section numbers below (§n) refer to it.

## Global Constraints

- Work on branch `feat/book-mode`, created from `docs/book-mode-spec` (it carries the spec and this plan).
- Single file `bin/repo-summarize`, first line exactly `#!/usr/bin/env -S uv run --script`, followed by a PEP 723 block: `requires-python = ">=3.12"`, `dependencies = []`. No third-party imports in the tool.
- Tests live in `tests/`, run with `uv run --with pytest pytest -q` from the repo root. The tool is loaded in `tests/conftest.py` with `importlib.util.spec_from_loader` + `SourceFileLoader`, because the file has no `.py` extension.
- Every prompt's first line is `STAGE: <catalog|plan|chapter|index|probe>`. The stub backend routes on it.
- Default backend argv: `["agy", "--disable-slash-commands", "-p"]`. The prompt is appended as the **last** argv element. `REPO_SUMMARIZE_CMD` is split with `shlex.split`.
- Limits (verbatim from the spec):
  - prompt ≤ 110 KB;
  - catalog batch ≤ 60 KB, 400 lines per file;
  - condensed catalog above 80 KB;
  - included file ≤ 100 KB;
  - binary = NUL in the first 8 KB;
  - chapter budget: instructions 8 KB, catalog context 12 KB, tests + manifest 4 KB, source = the remainder;
  - reply ≤ 64 KB;
  - ≤ 8 refs, each 5–40 lines;
  - identifier window ± 5 lines;
  - shim ≥ 80% import lines;
  - chapters: hard max 12, subsystems `clamp(round(f/15), 0, 9)`;
  - plan reuse: edge Jaccard distance ≤ 0.20 and new unassigned files ≤ 10%;
  - related to more than 3 chapters → related to 01 only;
  - timeout 300 s;
  - circuit breaker after 3 consecutive failures;
  - keep the last 3 run logs.
- Exit codes: 0 published · 1 failed · 2 usage · 3 aborted · 4 capped · 5 backend unsafe.
- Slug regex `^[a-z0-9][a-z0-9-]{0,40}$`. Generated Markdown starts with `<!-- repo-summarize:v3 run=<id> -->`. JSON files carry `"generator": "repo-summarize:v3"`.
- State lives in `docs/.repo-summarize/`: mode 0700, contains a `.gitignore` of `*`, cache files 0600. Logs never contain prompt or reply bodies.
- Never use the words "verified" or "supported" in generated output.
- Conventional commits, with no AI attribution trailers (per the user's CLAUDE.md).

## Review Focus

1. **A brand-new repo with no commits** (`git rev-parse HEAD` fails) or a non-git directory. Expected: it runs, `commit` is `null`, every link is a working-tree link, nothing crashes. *Test in Task 11.*
2. **Non-UTF-8 source files** (Latin-1 bytes). Expected: the snapshot copies the bytes, prompts decode with `errors="replace"`, line numbers stay intact. *Test in Task 2.*
3. **The backend wraps its JSON in code fences or adds a preamble.** Expected: the first complete JSON value is extracted and accepted, not treated as a failure. *Test in Task 5.*
4. **`agy` missing from PATH, or replying with an auth/login error on stderr.** Expected: a clear one-line error and exit 1 before any catalog work, with the lock released. *Test in Task 4.*
5. **Ctrl-C mid-run.** Expected: nothing published, previous book intact, lock released, cached replies kept so the re-run resumes. *Test in Task 11.*
